# Component Guide

> Generated by `/buddy:docs`. Feature-based layout: shared primitives at `app/components/` root, feature directories own their components/hooks/stores. Design rules in `AGENTS.md` bind all UI work; hierarchy comes from typography, grouping, proportion, and state treatment — not only borders and whitespace.

## Shared primitives (`app/components/`)

### `TransitionLink`
`app/components/TransitionLink.tsx` — a `next/link` that routes through the View Transitions API so route changes read as one continuous sheet (the "plotter wipe" in `app/effects.css`). Falls through to plain navigation when the API is missing or `prefers-reduced-motion` is set. The transition waits on the destination declaring itself ready via `app/lib/route-ready.ts` (pages render `RouteReady`, the Library signals from `SceneWheelV2`), bounded by `READY_BUDGET_MS` (900 ms, measured — see `specs/20260821-page-transitions-upgrade/research.md`). Direction along the nav order is exposed as transition types **and** `html[data-nav-direction]`; guard logic is pure (`app/lib/nav-direction.ts`) and covered by `npm run test:transitions`. Do not await `requestAnimationFrame` inside the transition's update callback — rendering is suspended there and it deadlocks (see `docs/transitions-qa.md`).

```tsx
import TransitionLink from "@/app/components/TransitionLink";

<TransitionLink href="/workbench">Workbench</TransitionLink>
```

Props: everything `next/link` accepts; `href` must be a string. Modified clicks (new tab etc.) are left to the browser.

### `SiteNavigation`
`app/components/SiteNavigation.tsx` — fixed nav with the sliding ink pill (`useNavPillSlide` + `.nav-pill` rules in `effects.css`). Active route is encoded via `data-active`.

### `DitherReveal`, `CountUp`, `DropdownSelect`
- `DitherReveal.tsx` — dithered image reveal treatment.
- `CountUp.tsx` — numeric count-up display.
- `DropdownSelect.tsx` — custom dropdown (custom controls are required where defaults fall short, but keyboard behavior and accessibility must be preserved — `AGENTS.md`).

## Workbench (`app/components/workbench/`)

Node-based editing surface built on `@xyflow/react`.

| Module | Role |
|---|---|
| `WorkbenchApp.tsx` | Surface root; wires the store to the canvas |
| `store.ts` | Zustand store — node graph, wire validation (`connectionIsValid`, `portSpecFor`), downstream invalidation (`downstreamOf`), draft signatures, edit-run IDs |
| `Inspector.tsx` | Selected-node property panel |
| `nodes/` | Node implementations (+ `nodes/shared.tsx` for common node chrome) |
| `signature.ts` | Draft signature computation (change detection; tested in `tests/workbench-draft-signature.test.mjs`) |

Rules of engagement (foundation Principle 3): inventory interactions before changing behavior (`docs/workbench-interaction-inventory.md`), and run `npm run test:workbench` — persistence migration, cancellation, cost, registry, import validation, and export/import all have dedicated suites.

## Scene surfaces

### `scene-wheel-v2/`
R3F scene for the Library: `SceneWheelCanvas.tsx` (canvas root), `SceneCard.tsx` (textured card planes), `curve-model.ts` (wheel geometry).

### `scene-lab/`
R3F development surface: `SceneLabCanvas.tsx`, `ScenePlane.tsx`, `WorldScenePlane.tsx`; geometry/assets/navigation logic in `app/lib/scene-lab-*.ts`. Deterministic QA via `useSceneLabQA` (`?qa=1&progress=…`).

Rendering-stack choice between DOM/CSS 3D and R3F must be justified per `AGENTS.md` — WebGL only where recordings show texture-plane behavior, depth compositing, or camera motion CSS cannot reproduce.

## Styling system

| File | Role |
|---|---|
| `app/globals.css` | Design tokens (`--background`, `--ink`, `--accent`, `--line`, …), base element rules, focus states |
| `app/effects.css` | Interaction effects: focus-grid hover, nav pill, page-transition (plotter wipe) pseudo-element rules |
| `app/motion-tokens.css` | Motion tokens (`--duration-*`, `--ease-*`) |

Conventions:
- New motion MUST use the duration/easing tokens and carry a `prefers-reduced-motion` fallback (foundation Principle 5).
- Colors come from the token set in `globals.css`; the palette is paper/ink with a pine accent.
- Tailwind 4 is available, but the deliberate visual system lives in the token CSS — match existing idiom when extending it.

## Accessibility notes

- Focus visibility is defined globally in `globals.css` (`:focus-visible` outline).
- All animated components ship reduced-motion fallbacks (`effects.css` media queries, `TransitionLink`'s runtime check).
- Custom controls must preserve keyboard behavior (`AGENTS.md` generator rules).
