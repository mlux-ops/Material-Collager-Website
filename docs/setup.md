# Developer Setup

> Generated by `/buddy:docs`. Quick-start also lives in `README.md`; this page adds the details.

## Prerequisites

- **Node.js >= 22.13** (`engines` in `package.json`; tests rely on `--experimental-strip-types`)
- **npm** (lockfile is committed; use `npm ci` for clean installs)
- An **OpenAI API key** for generation features
- No Cloudflare account needed for local dev — Miniflare simulates D1/R2 bindings

## Install

```bash
git clone https://github.com/mlux-ops/Material-Collager-Website.git
cd Material-Collager-Website
npm install
cp .dev.vars.example .dev.vars
```

Fill in `.dev.vars` (git-ignored; Miniflare reads it the way Workers reads production secrets):

```ini
OPENAI_API_KEY=sk-...
# Optional overrides:
# BFL_API_KEY=...
# MATERIAL_COLLAGER_ANALYSIS_MODEL=...
# MATERIAL_COLLAGER_MATCH_MODEL=...
# Leave CF_ACCESS_TEAM_DOMAIN / CF_ACCESS_AUD blank locally (no Access proxy on localhost).
```

## Run

```bash
npm run dev
```

Runs `vinext dev` on Miniflare with the bindings declared in `wrangler.jsonc`. Open the URL shown in the terminal.

**Workers AI caveat**: the `AI` binding (used by `/api/workbench/inpaint`) proxies to Cloudflare's network even in local dev — it needs a logged-in `wrangler` session and consumes the account's free-tier neurons.

## Tests

Node's built-in test runner, one suite per concern:

```bash
npm run test:collage
```

```bash
npm run test:workbench
```

```bash
npm run test:scene-lab
```

```bash
npm run test:access
```

```bash
npm run test:release-readiness
```

Notes:
- Workbench suites run with `--test-isolation=none` (shared setup); keep new workbench tests compatible.
- `tests/test_*.py` cover the legacy Python CLI under `Material Collager/` and are not part of the npm scripts.

## Lint

```bash
npm run lint
```

## Build

```bash
npm run build
```

Produces the Worker bundle under `dist/` (including `dist/server/wrangler.json`, patched at deploy time — see [deployment.md](deployment.md)).

## QA states

```
http://localhost:3000/?qa=1&progress=0.40
```

Required viewports and progress states are mandated in `AGENTS.md`; log discrepancies in `docs/visual-qa.md`.
